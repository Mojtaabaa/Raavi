# ADR-034 — AI assistant on pages (Phase 11a)

**Status:** Accepted (2026-11-08)

## Context

Phase 11 covers AI providers, embeddings, RAG with ACL, summarisation/writing and integrations. The product owner chose **an OpenAI-compatible provider per tenant** (key stored encrypted per tenant). 11a delivers the provider plumbing and the features that need no index: summarise a page and ask a question about one page. Embeddings/RAG over whole spaces (11b) need a retrieval store and are a separate slice; integrations (Jira/GitHub/…, webhooks) are later slices (11c+).

## Decisions

1. **Provider = OpenAI-compatible HTTP** (`POST {base}/chat/completions`), covering OpenAI, DeepSeek, Ollama, vLLM and similar. It sits behind `IAiChat` so another protocol is another class. **Deviation from ADR-016:** the interface is our own (`IAiChat`, messages in, text + token counts out) instead of Microsoft.Extensions.AI's `IChatClient`, because that package could not be added in this environment; the shape is deliberately close so adopting `IChatClient` later is a mechanical change inside the module.
2. **Settings per tenant** (`ai.Settings`, one row): enabled, base URL, model, API key, monthly token cap, maximum answer length. The key is stored only **protected** (ASP.NET Data Protection with a purpose bound to the tenant id), is write-only through the API (`hasApiKey`), is held in memory only for the call and never logged or put into errors. Saving requires a tenant administrator and uses ETag/If-Match after the first save; AI cannot be switched on without a key.
3. **Egress policy (SSRF).** A tenant chooses its provider address, so the installation controls where it may point: `Raavi:Ai:AllowedHosts` (exact names or `*.suffix`, empty = AI off everywhere). Loopback, link-local (cloud metadata), multicast and unspecified addresses are refused even if listed and re-checked at connect time after DNS resolution; redirects are never followed; http is allowed only for allow-listed hosts (on-premises model servers). The policy is applied when saving *and* when calling, so tightening it takes effect immediately. Provider responses are capped at 1 MB.
4. **Permissions — the context rule.** The AI module never reads content itself. The page text arrives through `IPageTextReader` (implemented by the Wiki module with the normal `PageService.LoadAsync` View evaluation **for the current user**). No access, unknown id, other tenant, non-page, archived/trashed: the same answer `ai.page_not_found` (404), **before** any quota is touched and before any model call. Only the one page the user asked about is sent; nothing else from the space.
5. **Prompt hygiene.** The system prompt states that the document is untrusted data and that instructions inside it must be ignored; the document is delimited and the user's request comes after it. Long pages are cut at `MaxInputChars` (24 000) and the model and the user are told. Answers are plain text and the UI renders them as text, never as HTML. This reduces prompt-injection impact; it cannot eliminate it, and the answer is labelled as machine-generated ("check important facts").
6. **Accounting and limits.** `ai.Usage` stores who, which feature, model, token counts, outcome and error code — **no prompt, no answer, no page content**. A tenant-wide monthly token cap (0 = unlimited, UTC calendar month) and a per-user hourly request limit (`MaxRequestsPerUserPerHour`, default 20; failed calls count) answer with 429 (`ai.quota_exceeded`, `ai.rate_limited`) before the provider is called. Providers that report no usage get an estimate (≈ 4 characters per token) so caps still bite. Administrators see this month's totals, per feature and top users.
7. **Failures** are mapped to stable codes (`ai.provider_auth|rate_limited|not_found|unavailable|rejected|bad_response`, HTTP 503) without the provider's body. Timeouts: 60 s per call. No automatic retry or fallback provider in 11a.
8. **Module layout.** `Raavi.AI` owns its DbContext (schema `ai`, RLS, migrations applied by the Migrator like the Migration module) and endpoints (`/ai/status`, `/ai/pages/{id}/summary`, `/ai/pages/{id}/ask`, `/ai/settings`, `/ai/usage`). A new `ErrorKind.TooManyRequests` maps to HTTP 429.

## Deferred

11b embeddings and retrieval-augmented answers across a space (needs a vector store; SQL Server 2016 compatibility level 130 has none, OpenSearch is deferred) with ACL-filtered retrieval and leakage tests across chunks; writing assistance inside the editor (rewrite/translate selection), streaming answers, retry/fallback and several providers per tenant, per-user quotas, prompt/answer audit option, Claude and other non-OpenAI protocols, cost estimation in currency, AI-triggered workflow actions.
