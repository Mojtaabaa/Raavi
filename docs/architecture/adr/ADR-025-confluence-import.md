# ADR-025 — Confluence Import (REST source, idempotent importer, jobs)

**Status:** Accepted (Phase 8, 2026-11-07). Complements CONFLUENCE_MIGRATION.md.

## Context

CONFLUENCE_MIGRATION.md describes the whole pipeline. Phase 8 starts with the REST source (the customer's Data Center 10.2.13 test server) and builds the importer so that XML backups, attachments and permission mapping can be added later without redesign.

## Decisions

1. **Provenance in the Wiki module is the idempotency record, not a separate mapping table.** Imported spaces, pages and versions carry `SourceSystem` (`confluence:{12 hex of the source address hash}`), `SourceId` (space key / content id) and, for versions, `SourceVersionIdentifier` (the source version number). Filtered unique indexes enforce one row per source item and one version per source number. This supersedes the `MigrationSourceMappings` table in CONFLUENCE_MIGRATION.md §6: a mapping kept in another DbContext could not be written in the same transaction as the page, so a crash between the two could duplicate content; unique indexes in the same table cannot. Re-running an import therefore never duplicates anything, and a resume downloads only versions that are missing (`ImportedVersionsAsync`).
2. **The Migration module never touches Wiki internals.** It talks to `IContentImporter` (Application abstraction, implemented by `ContentImporter` in Wiki). Each page (all its new versions, labels, closure rows) is one transaction and is validated by the editor schema first; a failing page changes nothing. The importer emits **no** wiki events (no activity-feed or notification flood).
3. **History.** Versions are numbered 1…n in source order with `VersionType.Import`, the original time, comment and author. Authors are *not* mapped to Raavi users yet (nobody is invented): the source identity is kept in `PageVersion.SourceAuthorJson` and listed in the report as unmapped.
4. **Never widen access.** An imported space is created with every space right granted to the importing administrator only (no member or group grants). Source permissions and restrictions are not imported yet; importing them (with "restricted to space administrators" on anything unmappable) is a later step.
5. **Jobs.** `MigrationDbContext` (schema `migration`, RLS) holds `Jobs` and `Events`. A job belongs to the tenant of the creating administrator; the Hangfire tenant job re-checks that the owner is still an active tenant administrator when it runs. The source token is stored only protected (ASP.NET Data Protection, purpose bound to the tenant), is erased when the job finishes (kept for a paused job so it can resume) and never appears in a response, event or report. Pause/cancel are flags (`Control`) written with a single atomic update and honoured between pages. Resume = start again.
6. **Dry run** performs discovery, download and conversion and produces the same report without writing to the workspace. **Execution** adds: parents before children, home pages, a link pass (placeholders `raavi:confluence-page?space=&title=` → `/spaces/KEY/pages/{id}`; unresolved links are removed, their text kept, and reported), and per-space page-count validation.
7. **Source safety.** Only hosts in the global allow-list `Raavi:Migration:AllowedSourceHosts` are contacted (empty = disabled); loopback, link-local (cloud metadata) and multicast addresses are refused even when listed and again after DNS resolution (connect callback); redirects are not followed; only GET requests are made.
8. **Version discovery.** The REST adapter probes `/rest/api/content/{id}/version` and falls back to `/rest/experimental/content/{id}/version` (the only one on Data Center 10.2.13), remembering the answer.
9. **Hangfire tenant jobs.** `TenantJobRunner` became a generic *class* `TenantJobRunner<TJob, TArgs>`. Hangfire stores closed generic types but not the type arguments of generic *methods*, so the previous design enqueued jobs that no worker could ever execute (found while running this phase end to end; it also affected scheduled publishing). A regression test round-trips a scheduled job through Hangfire's real serializer.

## Addendum — attachments, people, restrictions, dynamic lists (Phase 8b)

10. **Attachments** are stored with the page (attachments-lite, bytes in SQL; S3 is deferred). Their id is **deterministic**: SHA-256 of tenant, source system, source page and file name (`ImportIds.Attachment`). The converter therefore points an image at its file before the file exists, and a re-import hits the same row. The **tenant is part of the hash** because attachment keys are global — found by a test where two workspaces imported the same source. Only the latest version of a file is imported; files above `Raavi:Attachments:MaxBytes` (the product's upload limit) are left out and reported; a failing download is recorded and never stops the page. Images that show *another page's* file stay without a file (reported, `image.other_page`). A download whose size disagrees with the source's own metadata is kept and flagged (`attachment.size_mismatch`): on the test server four JPEGs were once stored as the file twice over although later downloads are byte-exact, and its size metadata disagrees with the content too — the source is inconsistent, so the import is defensive instead of trusting it.
11. **Re-convert** (`reconvert` job option) re-reads every version and refreshes what was imported by an older converter: changed bodies are rewritten in place (history, numbers and dates are kept), missing authors are assigned, and attachment bytes that differ are replaced. It is how converter improvements and repairs reach already-imported data.
12. **People are never matched implicitly.** Authors and restriction subjects are matched to workspace members through an explicit map (`userMap`: source user → member e-mail) or, only when the administrator turns on `mapUsersByEmail`, by **verified** e-mail. A dry run lists suggestions (source user, e-mail, suggested member); nothing is applied until confirmed. Groups map by exact name to existing workspace groups. Unmapped authors stay as source identities (`SourceAuthorJson`).
13. **Restrictions never widen.** A page restricted in the source is restricted to the mapped users and groups **plus the importing administrator**; subjects that could not be mapped are left out and reported. A kind of restriction is only applied when the page has none yet, so a re-run never overwrites changes administrators made later. **Space permissions are not imported**: the test server's REST API does not expose them (HTTP 500 for the migration user); spaces stay visible to the importing administrator only and the report says so. Importing them needs the XML backup reader.
14. **`children` and `contentbylabel` become dynamic lists** — editor nodes `raavi.children` (depth 1–5) and `raavi.contentByLabel` (labels, max items, this space only). They are computed when the page is viewed from the page tree and the labels API, so they only list pages the viewer may see (no stale copy of a list that depends on who looks). The converter maps what it can express (the page's own children; `labels`, simple CQL `label = "x"` / `label in (…)`, `type=page`, `spaces` = this space) and keeps everything else (another page's children, other spaces, other content types, complex queries) as an unsupported node with the escaped source. The server-side HTML renderer marks the place only.

## Addendum — comments (Phase 8c)

15. **Comments are imported as threads, never as invented people.** Page and inline comments (the quoted text becomes the inline anchor, ADR-024), the resolved state and the original time are kept; replies at any depth are flattened into their thread (threads are flat, ADR-024 §2). `Comment.AuthorId` became nullable: an author who is not (yet) a workspace member is kept as `SourceAuthorName` and the comment has no owner — nobody can edit it, administrators can delete it. Mapped authors (explicit map or confirmed verified-e-mail match, ADR-025 §12) become real authors. Imports write **no outbox events**, so nobody is notified or auto-watched. Idempotent by (source system, source comment id) with a filtered unique index. An empty or invalid comment is skipped and reported; an inline comment without quoted text becomes a page comment. Only the latest body of a comment is imported (no edit history). Comments already imported are not refreshed by re-convert.

## Consequences

- Migration needs the Workers host (Hangfire) and a shared Data Protection key ring between API and Workers (already required for sessions).
- Page-level source failures are recorded and the job ends `CompletedWithErrors`; source authentication/connectivity failures end it `Failed`.
- Attachments (7b is deferred: they will use attachments-lite bytes in SQL), user/group/permission mapping, comments, blog posts and the XML backup reader are not part of this step.
